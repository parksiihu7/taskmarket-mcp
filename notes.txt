1. EVERY CLAIM ABOUT TASKMARKET, AND THE FACT-SHEET LINE BEHIND IT
-----------------------------------------------------------------
The fact sheet is in the brand kit (0-TASKMARKET-BRAND-KIT.md, section "Fact sheet"), commit
af55554d77b0627ff96b52a82a2f3b94b9cab387. Line numbers are that file's bullet order in the list under
"Only these claims."

claim: Taskmarket is a marketplace where agents and people post paid tasks and do them
  used in: README (first line), listing.md (description), server.mjs (server instructions)
  fact sheet: bullet 1 — "Taskmarket (https://taskmarket.dev) is a marketplace where AI agents and people post
  paid tasks and do them."

claim: a reward is held in escrow before anyone starts, until the requester accepts a result or reclaims it
  used in: README ("Safety"), listing.md ("Rewards stay in escrow until a requester accepts"),
  server.mjs (list_task_modes note)
  fact sheet: bullet 2 — "A requester posts a task with a reward. The reward is held in escrow on-chain before
  anyone starts, until the requester accepts a result or reclaims it."

claim: rewards are paid in a stablecoin, USDC on Base and OUSD on Tempo
  used in: README (filters paragraph), listing.md (description), tool descriptions (network: tempo = OUSD,
  base = USDC), and the currency field of every task the tools print
  fact sheet: bullet 3 — "Rewards are paid in a stablecoin: USDC on Base, OUSD on Tempo."

claim: the five modes, in the words list_task_modes prints
  bounty "many workers submit; the requester picks one or more winners", claim "one worker reserves the task",
  pitch "workers pitch; the requester selects one", benchmark "entries are ranked on a metric",
  auction "workers bid on price"
  used in: list_task_modes, README (tool table), listing.md
  fact sheet: bullet 4 — "Task modes: bounty (many submit; the requester picks one or more winners), claim (one
  worker reserves the task), pitch (workers pitch; the requester selects one), benchmark (entries ranked on a
  metric), auction (workers bid on price)."

claim: workers submit, the requester accepts, the reward is released from escrow to the winner or winners
  used in: README ("what it asks" is phrased from this), list_task_modes note
  fact sheet: bullet 5 — "Workers submit their work; the requester accepts it; the reward is released from escrow
  to the winner or winners."

claim: requesters can limit a task to verified workers, by TAP verification
  used in: the verifiedOnly filter and the verifiedWorkersRequired field; README and listing.md name it as the
  CLI does (--verified-by tap:identity:verified)
  fact sheet: bullet 6 — "Requesters can limit a task to verified workers, for example TAP verification: the
  agent's signing key is listed in Visa's agent directory after its owner verifies once with a Visa card."

claim: the CLI is the tool the server's filters are checked against
  used in: transcript.md section 2 and 5, test/parity.mjs
  fact sheet: bullet 9 — "Agents use the command-line tool: npm i -g @lucid-agents/taskmarket"

Two things could not be exercised in the machine this was built on, and are stated rather than claimed:
  - "npx -y github:parksiihu7/taskmarket-mcp" — this sandbox refuses git network operations by policy
    ("GitHub is not connected"), so the npx route was not run here. The repository's own tarball route above was
    run instead, from the same commit. On a machine with git, the npx line is the standard way to run a public
    repository package and needs no install step.
  - The desktop clients (Claude Desktop, Cursor, VS Code) cannot run in this environment. transcript.md is a real
    session with the MCP SDK's own client over the same stdio transport those clients use; it says so in its
    first paragraph.
